Overview

Most popular fiction has no table of contents. The reader is expected to read through, perhaps placing a bookmark (or face the open book down) as a pause. This is also true of some nonfiction.

A table of contents should be used when the book is a collection of short stories, especially when they are unrelated, or have different authors.

Occasionally, a novel has chapters so distinctive that they are self-contained episodes. In this case, an optional table of contents is essentially an outline of the plot.

In all cases, do not use a table of contents, unless each entry has it own title, not just Chapter N for various N. Portions such as Introduction and Prologue are considered to be titles.

Novelette does not design the table for you. You must design it yourself, using the environment and commands described below.

Where to place the table, and what must it contain (or must not contain)? Novelette does not care, as long as the component containing the tableis in frontmatter. Search the Internet for "book design" advice.

 

General Information

TOP

As usual, everything must be contained within a component environment.

  • The table uses the toc environment, containing \entry commands.

    There are two basic formats for the table: centered entries, and vertical sides. They are explained lower on this page.

  • You cannot use graphics or \styleN within toc, and you cannot nest another toc or block environent. But you may place these things in the same component, outside the toc.

    In particular, the table's title is outside the block.

  • The table may extend for more than one page. You may also create more than one table, on the same page.

  • You do not need the \maintext command, although its use is not a problem. All of the material may sit within the display zone.

 

Table Title

TOP

Use \styleN for the table's title. In many cases, the design will look better if there is some vertical space above the title.

The title may be Contents or something else. One possibility is to use the title of the book, as title of the table. This is especially useful if the book is a collection of short stories.

You may place a short dedication or epigraph between the title and the table. Then, you do not need to place that material on its own page.

Example: This is for a book titled The February Tales, which is a collection of short stories. Instead of a dedication or epigraph, there is a quick remark between the title and the table:

\begin{component}
\blankline\blankline
\style2{The February Tales}
\blankline
\style6{\textit{for those who love it cold}}
\blankline
\begin{toc}[format=center,pad=.5]
% table entries here
\end{toc}
\end{component}

 

Environment: toc

TOP

Use the toc environment as a wrapper for the table entries:

\begin{toc}[format=F,pad=P] ... entries ... \end{toc}

  • F -> Either center or N, where 0<=N<=8 is a number. Default center.

    This selects whether the format uses centered entries or vertical sides, as explained lower on this page.

  • P -> Number 0<=P<=1. May be decimal. Default 0.

    Non-zero P applies vertical padding above each \entry (but not above other material). The padding is measured as multiple of normal baselineskip. Thus, pad=.5 applies half‑skip padding.

 

Table Entries

TOP

Write each table entry with the \entry command. If you need ordinary text between entries, you may write it; but better results will be obtained if you break the table into several tables, with other material between them.

The \entry command takes four mandatory arguments, possibly followed by an optional argument:

\entry{id}{which}{name}{bookpage}[subname]

  • {id} -> Refers to a subsequent component id.

  • {which} -> May be an integer 1–99, empty, or the < symbol.

    • If the entry is a numbered chapter (or something similar), use its number. Digits only, no punctuation. The number will print, and Novelette will automatically follow it with period and space.

    • If the entry has no number (such as Prologue), use either empty braces or {<}. The symbol does not print. There is no difference when the table format is center.

    • When the table format uses vertical sides: {} prints the {name} aligned in the column with other names. {<} shifts the {name} left, to the start of the {which} column.

    • No cheating: You cannot write anything else, such as {A} for {which}.

  • {name} -> Is the chapter name, or short story name, or other things such as Prologue, etc.

    If your book contains chapters without names, then you should not be using a table of contents!

  • {bookpage} -> The page number seen in print. May be italic or arabic. Usually not the same as the PDF page number.

    Some pages do not print their numbers. In this case, bookpage is the number that you would see, if it printed.

    Novelette does not have automatic page numbering. Until you know the page numbers, you may leave the bookpage as empty braces. Then, ### will print as a placeholder bookpage number.

  • [subname] -> Optional, short text, printed beneath the entry.

    If your book is a collection of short stories with different authors, write the story title as entry names, and the authors as subnames. Or, a subname may be a "teaser", which is a brief hint about the story or chapter contents.

    The subname prints at small size, and is aligned in the column with ordinary names. You may use \indent if you prefer it to be indented. The subname may have more than one paragraph.

    If the subname has printable braces, use \[ and \] to avoid confusion.

 

Alternative: [format=center]

TOP

Each entry prints centered, similar to the following:

14. Stormy Weather . . . 183

The number (but not hyphen) prints, followed by period and space. Then the name is followed by exactly three spaced dots, then the bookpage. Example:

\begin{component}
\blankline\blankline
\style3{The February Tales}
\blankline
\style5{\textit{for those who love it cold}}
\blankline
\begin{toc}[format=center,pad=.5]
\entry{pro}{<}{Prologue}{1}
\entry{wf}{1}{Wicked Flakes}{3}
\entry{ys}{2}{Yellow Snow}{18}
\entry{snsu}{3}{Snowman's Surprise}{32}
\entry{whfo}{4}{When Hell Freezes Over}{68}
\entry{sco}{5}{School's Out}{103}
\entry{slsl}{6}{Slithering Sleet}{142}
\entry{sch}{7}{Snowball's Chance}{166}
\entry{cfs}{8}{Cold Fudge Sundae}{195}
\entry{stk}{9}{Slick Talk}{218}
\entry{oog}{10}{Out of Gas}{256}
\end{toc}
\end{component}

 

Alternative: [format=N]

TOP

If you use \begin{toc}[format=N] then the entries are block-aligned. Its sides are offset N normal indents from the margins. Thus, larger N means narrower table.

The table has three columns: number, name, bookpage.

  • The number column prints each numerical chapter number, followed by period and space, right-aligned. But if an entry has no number (empty or <), nothing prints there.

  • The name column prints each chapter name, left-aligned, followed by spaced dots. As many dots are provided as needed to fill the column.

    When an entry number is the < symbol, its name is moved to the left, to align with the start of the number column. When an entry number is empty, its name remains in the name column.

  • The bookpage column prints each bookpage number, right-aligned.

Example: Here, the Prologue has empty braces for the chapter number. That aligns Prologue to the start of the number column. If instead it used {-} as number, then Prologue would print aligned to Wicked Flakes and the other names.

\begin{component}
\blankline\blankline
\style3{The February Tales}
\blankline
\style5{\textit{for those who love it cold}}
\blankline
\begin{toc}[format=3,pad=.5]
\entry{pro}{<}{Prologue}{1}
\entry{wf}{1}{Wicked Flakes}{3}
\entry{ys}{2}{Yellow Snow}{18}
\entry{snsu}{3}{Snowman's Surprise}{32}
\entry{whfo}{4}{When Hell Freezes Over}{68}
\entry{sco}{5}{School's Out}{103}
\entry{slsl}{6}{Slithering Sleet}{142}
\entry{sch}{7}{Snowball's Chance}{166}
\entry{cfs}{8}{Cold Fudge Sundae}{195}
\entry{stk}{9}{Slick Talk}{218}
\entry{oog}{10}{Out of Gas}{256}
\end{toc}
\end{component}

 

Bookpage Numbers: Not Automated

TOP

Novelette does not automatically populate the table with correct bookpage numbers. You must write them yourself, when you are nearly finished, and you know which components start on which book pages.

When compiling a sub-document, bookpages are meaningless; Novelette pays no attention to them.

When compiling the whole document, Novelette reads the table of contents, and remembers which id is supposed to be at which bookpage. When it subsequently reaches that component id, it checks whether its actual bookpage is what the table said. If they disagree, you will be warned, and informed of the correct number. Then you must edit the table manually.

The document jobname.typo file will contain what you need to know.

The Novelette developer believes that this method is less likely to cause problems, if you exchange documents with a human editor. That may sound complicated, but it is actually how things were done, until very recent times. Did Dickens, Goethe, Rabelais, or Cervantes have automated page numbering? No! They wrote great books without it. So can you. Maybe.
