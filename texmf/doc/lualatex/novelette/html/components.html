Overview

Novelette has no commands or environments for part, chapter, section, or similar divisions. If you try to use those standard LaTeX methods, an error results.

Instead, Novelette thinks of the document body as divided into numerous components, which have no pre-defined meaning. There is no rank, no hierarchy, no sub-component.

 

Component Environment

TOP

With the exception of page headers/footers, all printed content must be contained within a component environment:

\begin{component}[option]
(content of display zone)
\maintext
(content of main text)
\end{component}

  • The contents of the environment may be as short as one page, or extend for many pages. In all cases, the component begins with a new page, and ends with a new page.

  • When a component begins, it creates a display zone, which allows effects that are not available in main text.

  • Command \maintext exits the display zone. Do not confuse this command with \mainmatter.

  • Commands \frontmatter \mainmatter \backmatter may only be used between components, never within a component. One of those commands (usually \frontmatter) must precede the first component in the document body.

  • A component may not contain a sub-document, and may not contain another component.

  • You may use \newpage and \clearpage within a component.

  • A component is often used as a chapter, but there is no automatic chapter numbering. Use placeholder \next until you know the numbers.

 

Display Zone

TOP

Each component begins with a display zone. It may be empty, but that is unusual. It may occupy the entire component, which is typical for the title page and other special pages.

Most often, the display zone occupies part of the component's first page, followed by main text lower on that page. Then, the main text continues to additional pages. This is typical for chapters.

Within the display zone, you may use styling commands that are unavailable elsewhere. Full description is provided here.

 

Main Text

TOP

The \maintext command ends the display zone. If the display occupies the entire component, do not write \maintext.

At \maintext, one or two blank lines are added automatically. It will be two, unless the component uses option [style=drop], in which case, only one.

At this point, the text baseline is probably off‑grid, due to the varying heights of styled text in the display zone. Novelette calculates how much vertical space is needed to restore the baseline to grid, then automatically adds that space.

Following \maintext, you may:

  • Use \init or \dcap commands, where allowed.

  • Place images. They may float, where allowed.

  • Use \footnote where allowed. Its marker prints.

  • Use \scene where allowed.

  • Place the block environment, but it must have normal text, not small.

  • Write ordinary text. Usually (not always) this is the text of your story.

 

Guide Mark

TOP

The content and spacing of the display zone, determines where the first line after \maintext will print. Standard practice (not mandatory) is to tweak the display zones, so that each \maintext prints at the same vertical position.

To help you find that position, Novelette provides a guide marker. It only prints in draft mode. The marker is lowercase g with the baseline shown, appearing in the left margin next to the text.

The global default guide position, counted in normal lines, is set in preamble by \enable{guide=G} for integer G. Default G=0 means no guide.

You may locally change the value per‑component using option [guide=G].

You choose whether or not to obey the guide. Missing it is not a problem.

 

Component Option

TOP

Most components do not need an option.

\begin{component}[class=C,style=S,guide=G]

  • C -> Choices: normal single legal. Default normal.

    • normal -> Content may extend for one or more pages.

    • single -> Allows image at full textblock height. Warns if content exceeds one page.

    • legal -> Warns if content exceeds one page. Warns if page is not verso. Applies special rules to content (see below). Useful for copyright page.

  • S -> Choices: normal plain empty drop layout. Default normal. Applies only to first page of the component.

    • normal -> Becomes plain or empty, depending on location.

    • plain -> Header does not print. If layout has footer, it prints. This is the default in mainmatter.

    • empty -> No header or footer prints. This is the default in frontmatter and backmatter.

    • drop -> Known as drop folio (not drop cap). Header does not print. If layout has footer, it prints. If layout does not have footer, then the height of the textblock is reduced by one line, and a fake footer (page number) prints where the last line would ordinarily be located.

      Only use this option when necessary. That might be the case if your book is a collection of short stories, listed by page number.

    • layout -> Forces page style set by \layout, even if header/footer would normally be empty on the first page.

      This might be useful if the component is a single page in mainmatter, containing only an image.

  • G -> Integer 0 - lines per page. Over‑rides the default set by \layout.

 

Option [class=legal]

TOP

This is a special case. The content of the component is neither display nor main text, but has its own set of rules, optimized for showing basic legal information.

Using [class=legal] is recommended, but not mandatory, for the copyright page. Unless you have a better design method, use it there. You may also use it elsewhere, but that is unusual.

A legal page sets page style and text format, but it does not communicate with PDF metadata. It is your responsibility to ensure that the information matches.

Behavior of a legal page:

  • A warning is issued if the legal content does not fit on one page.

  • If the page is recto, then a warning is issued. This does not apply when compiling a sub-document, because its page numbers are unknown.

  • The \maintext command, if used, will be ignored.

  • You may use Italics and small caps.

  • You may not use the block environment.

  • You may not use any \styleN \scene \init \dcap.

  • Numerals will always be lining. Requests for oldstyle will be ignored.

  • You may use non-floating images. Do not write essential copyright information as images; it must be machine‑readable ordinary text. Only use images for such small things as a publisher's logo.

  • The [style=S] option is disabled. Page style will always be empty.

  • The [guide=G] option is disabled. No guide.

  • Paragraphs are not indented. There will be a one-line gap between paragraphs.

  • Hyphenation is disabled.

  • The entire content will be horizontally and vertically centered.

  • You must use line breaks \\ so that the width of each line is much less than the full textwidth. Do not allow lines to wrap!

 

Changing Page Headers

TOP

Print-on-demand usually insists that the title and author of your book be the same, wherever they appear. That includes page headers. They headers will not print on some pages, but wherever they print, they will not change from place to place.

On the other hand, traditional book design, using production-run commercial printing, does change page headers. This is especitally true in frontmatter and backmatter. If you need this capability, and you know what you are doing, and your print service allows you to change page headers, it is possible:

  • The preamble must use the option [local] for its \vrheadtext setting.

  • Just after \begin{component}, write:

    \vrheadtext[local]{new verso}{new recto}

    The change is effective only for that component. It reverts to the preamble setting at the next component. Note that default in frontmatter and backmatter is empty header, regardless of the preamble setting.

  • This does not affect whether or not the first page of a component prints the header.
