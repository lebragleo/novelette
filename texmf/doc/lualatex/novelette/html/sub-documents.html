Overview

Best practice is to break your book into a number of files, rather than one large file. The single main document contains the preamble with settings, and calls for the content of its sub-documents.

Standard LaTeX has packages such as standalone, subfiles, and includeonly, that can help you break a large document into manageable pieces. Novelette does not use them, but instead has built-in commands. You will never use the \include command, and will only use \input once per sub-document, as described below.

 

Sub-Document File Structure

TOP

Every sub-document is a *.tex file. It must be located in the same folder as the main document, or (better) in a subfolder relative to the main document.

  • The top four lines of a sub-document must follow a specific format:

    %!TeX program = lualatex
%!TeX encoding = UTF-8
\def\thisdoc{M:PathFromMainDocumentTo/SubdocFilename.tex}
\input{PathFromSubdocTo/MainDocument.tex}

    • Above, M is one of frontmatter mainmatter backmatter. Do not use backslash. This must match where the sub-document will appear, when it is called by the main document. Its purpose it to let the sub-document know where it belongs, when compiled alone. Note that a colon follows.

    • \def\thisdoc tells the compiler how the main document will find this file. The path is relative to the main document, whether this sub-document is directly called by the main document, or called by another sub-document.

      When compiling the main document, \thisdoc is ignored. when compiling a sub-document, it ignores \thisdoc in its own sub-documents.

    • \input tells the compiler where to find the main document, when compiling just the sub-document. This command is ignored when compiling the main document; it does not re-input itself!

  • If a sub-document calls another sub-document, there does not need to be any particular relationship in the folder tree. As long as all files are within the same folder as the main document, or in levels beneath it, all paths are relative to the main document.

  • A sub-document has no \documentclass, no preamble settings, no \begin{document}, no \end{document}.

  • After the required top four lines, the remainder of the sub-document consists of material within component environments, or calls to other sub-documents.

  • You do not need to write any command to close a sub-document. You may write \endinput if you wish. If you do that, anything beneath it (in the same file) will be ignored by the compiler. This is a useful way to make notes to yourself.

  • Novelette performs a detailed sanity check on sub-document syntax.

 

Calling a Sub-Document

TOP

A sub-document is included in the main document, or in another sub-document, by a simple command:

\subdoc{PathFromMainDocumentTo/SubdocFilename.tex}

You cannot use the same sub-document more than once. This prevents recursion. If some content is repeated in your book, use multiple files.

 

Compiling a Sub-Document

TOP

To compile a sub-document, do the same thing that you would do for the main document. For example, if the subdocument is subdocs/chapters/chapter-1.tex relative to the main document, you would navigate to the subdocs/chapters folder, then command:

lualatex chapter-1

When you compile a sub-document:

  • The compiler reads the preamble of the main document, and executes routines to the end of \begin{document}. Then it transfers to the sub-document, and prints its content. Finally, it executes code in the main \end{document}.

  • The PDF and log file will appear in the current working directory, which is usually the same as the sub-document folder.

  • The metadata will be altered, so that it is not identical to the metadata of the complete book.

  • The result will not be PDF/X-1a:2001 format.

  • The sub-document cannot know what its page numbers will be. It will print zzz (if roman) or 000 (if arabic) where page numbers would print.

  • In most cases, the sub-document cannot know whether it will begin recto or verso. The side-margin glue strip will be split, so that the content does not shift from side to side.
