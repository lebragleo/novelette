Overview

If your book has any graphics, be sure to read this page! Novelette does not use any of the standard LaTeX methods for graphics.

Novelette is intended for books such as mystery novels, where there are not many images. It cannot accomodate the large number of images needed by "graphic novels".

Novelette cannot create the book cover. For that, you need other software. But there is some useful information about covers lower on this page.

 

General Information

TOP

Forget what you already know about LaTeX graphics. Ignore what your read at online LaTeX tutorials. Pay attention here:

  • Novelette has its own commands for inserting images. The standard LaTeX \includegraphics command is disabled.

    Only use png raster images. No jpg, or eps, or pdf.

  • No vector graphics. No TiKz, or pstricks, or svg.

  • Image files may be monochrome or true grayscale (not RGB).

    If you have a raster png or jpg images that do not meet specifications, (wrong color space, missing or too much metadata), Novelette provides shell scripts that can fix the problems for you.

  • The \image command inserts an image, in its own paragraph. Depending on where you use it, the image may or may not be able to float.

  • The \logo command inserts an image, inline with text. This command may only be used in certain areas, and the image size is very limited. It is intended for things such as publisher's logo.

  • The \scene command has option [image], which prints a limited-size image (instead of text) for use as scene break.

 

Starred and Unstarred Commands

TOP

Commands \image, \logo, and \sceneimage have starred versions \image*, \logo*, and \sceneimage*.

  • In preview and final modes, the starred and unstarred commands behave the same: The file must exist, be in an allowable path, fit its allowed width and height, and pass detailed inspection. The inspection takes time.

    In draft mode, the starred and unstarred commands have different behavior:

    • The starred commands behave like they will behave in preview and final modes, except that the time-consuming detailed inspection is not performed.

    • The unstarred commands do not look for the image file. It does not need to exist, and will be ignored if it does exist. The text in {PathTo/filename.png} may be anything, and may be empty (but you must write the braces).

      Instead, a gray placeholder rectangle is printed where the image will print, It displaces the same area that the image will displace, and (if float) floats to the same place. This compiles much faster than the starred commands, yet preserves the line breaks and page breaks. It allows you to "write your story now, design its images later."

 

Path and Filename

TOP

Have you ever archived or copied a work containing many files, only to discover that something is missing? Novelette feels your pain. For that reason, you must follow these rules:

  • Image file names must have the lowercase .png file extension.

  • File paths are always relative to the main document, even if the files are called by a sub-document.

  • You cannot use \graphicspath to change anything.

  • The names and paths may not contain spaces, or any character that is not a valid path/file name in all modern operating systems. No backslash. You may use hyphen or underscore.

  • No absolute paths: No Linux /home/john/. No Windows C://john/. No asciitilde ~/john/.

  • No symlinks (softlinks).

  • Files must be located in the same folder as the main document, or in a subfolder (maximum 5 levels) down from the main document.

  • Best Practice: Within the main document folder, create a folder for storing the finished png images, and another folder for storing their native-format graphics files. Then, if you ever need to edit them, you have the originals where they can easily be found.

 

Raster png Specifications

TOP

The png (Portable Network Graphics) raster image is the only format supported by Novelette. No exceptions. You cannot create TiKz drawings. You cannot include svg or eps or pdf files. This is intentional.

  • Novelette does not have \caption or anything similar, and cannot draw a frame. If you need these, you must design them into the image file.

    If the image has text (such as place names in a map), be aware that rasterization may reduce readability.

    Unless the text is bold or enlarged, best results will be obtained with the kind of sans‑serif font that is used for viewing programmer text. Fonts such as Roboto™ and NotoSans™ appear suitable.

    You may use Novelette fonts, but your graphics program may be unable to find them, unless you copy the fonts to your operating system fonts directory.

    Whatever fonts you use, it is your responsibility to ensure that the font license allows you to use them (rasterized) for commercial print.

  • Internally, each file must state its resolution (density). This is normal for graphics design software.

    Note: This documentation shows resolution in terms of pixels per inch. The png internal format stores it as the equivalent pixels per centimeter. This is automatic; have no fear.

  • Image color space must be either monochrome (black/white at 1‑bit per pixel), or single-channel grayscale (8‑bits per pixel).

  • Preview and final modes require that the files pass validation tests.

  • In most cases, files that do not meet all of the above requirements can be easily repaired using utility scripts that come with Novelette.

  • The file will print at its exact size, without rescale or other transform. Thus, a file that is 150x450 pixels at 300px/inch, will print at 0.5x1.5 inches.

  • Best Practice: Design graphics for print‑on‑demand.

    • A monochrome file (1‑bit per pixel) should use 600 pixels/inch resolution, or greater (if your print service allows it).

    • A grayscale file should use 300 pixels/inch. There is no advantage to using a higher value, although some print services prefer a slightly higher value.

    • The technology does a poor job with smooth gradients, and a poor job for grays that are close to white or black. When you process your files using Novelette's utility scripts, grays close to white are forced to white, and grays close to black are forced to black.

    • If possible, test your files by printing them with inkjet, and also by printing them with toner (like photocopier, but can read digital files). Be sure that only black ink is used, not CMYK.

The \image Command (Also \image*)

Usage: \image[option]{PathTo/filename.png}

Option: [lines=L,align=A,float=F,tweak=T].

  • L is an integer 1<L<(lines per page).

    Although it is written as an option, each \image must reserve the number of lines that it will occupy, in terms of normal text lines.

    If the image does not fit in its reserved area, it is a problem. It will not increase the area, and will not be printed somewhere else. Instead, a gray placeholder rectangle prints where the image should print, occupying the reserved space.

    If the image is shorter than its reserved space, it will be automatically padded to occupy the full reserved space.

    There is no default value for L. If an image does not fit, and you ignore the problem, the result will be wrong.

  • A is one of left right center.

    Horizontal alignment. Default center.

  • F is one of none here top bottom.

    In frontmatter, backmatter, and component display areas, only none permitted; it is the default.

    In main text, the default is here. Novelette automatically uses top as fallback for here. These have the same meaning as ordinary LaTeX.

    There are no "page" floats. If you need an image on a page by itself, use a component environment with [single] option. Then the image can (if desired) occupy the full textblock. This should never be done in the middle of a chapter, where it would break the text flow.

  • T is one of up down mid.

    When the height of an image is less than its maximum (for any particular lines=L), it will be padded above and/or below. Tweak changes where padding is applied. Choice up moves the image as high as it can go (all padding beneath). Choice down moves the image as low as it can go (all padding above). Choice mid is the default, which splits the padding.

    Tweak does not change where an image floats, and does not change the number of displaced lines.

Mandatory: {PathTo/filename.png}

  • In draft mode, unstarred \image does not look for an image file. It prints a placeholder, whether or not the file exists. You may use empty braces, or write a short note, such as {Map of Whereville}, as a reminder to yourself.

    If you write a reminder, do not use macros such as \textit or \smcp. Do not use diacritical codes such as \'E for Eacute. The reminder will print as a label, within the placeholder area (no more than final 32 characters).

  • Placeholder \image rectangles occupy the correct number of lines, and have the correct float, alignment, and tweak. But since the height and width of the real image is unknown, the placeholder occupies the maximum possible height for its reserved area, and about 2/3 the textwidth.

 

Image Dimensions

TOP

This applies to ordinary images, using the \image command. It does not apply to \logo or to \sceneimage commands.

  • Run a test document with your Preamble settings, in draft mode. The Terminal Summary will show the textwidth, font em size, and baselineskip. These are specific to your settings. If you change anything in Preamble, then the values may change.

  • The maximum width of an image depends only on the textwidth. For example, if the textwidth is 4.2in, a grayscale image at 300px/in cannot exceed 4.2*300 = 1260px width.

  • The maximum height of an image depends on font em size, baselineskip, and number of text lines that the image will displace. The number of lines is declared as option for the \image command.

  • Equation for calculating the maximum height of an image: P is its maximum height in pixels, L is the declared number of lines, em and baselineskip are measured in pt, and R is the image resolution in pixels/inch:

    • P = R*[0.84*em + (L-1)*baselineskip] / 72.27

      For example, if R=300px/in, L=5, em=11.7pt, and baselineskip=14.8pt:

      P = 300*[0.84*11.7+(5-1)*14.8]/72.27 = 286 pixels.

      The actual calculation is a little more than 286, but the value must be truncated down to an integer value. Never rounded up.

    • Or, if you already know the pixel height, you may calculate the minimum number of lines required:

      L = 1 + [(72.27*P/R) - .84*em] / baselineskip

      Round L up (never down) to nearest integer.

  • Unsure of the book trim size, or other Preamble settings? If you design images so that they do not exceed 3.4in width and 3.4in height, then they will fit all sizes provided by Novelette, although the number of displaced lines will vary.

    That height allows for at least 7 lines of text on the same page as an image. Better results will be obtained if you first decide on trim size and layout, then decide on the displacement for each image, then design the images.

  • When an image is at or near its maximum height, the above/below clearance to text will be adequate, but not very great.

 

Command: \logo (Also \logo*)

TOP

A Novelette "logo" is a special kind of image. It may be used inline with text. Its purpose is to print something such as a publisher's logo, in places such as the title and copyright pages; but Novelette does not know or care why you use it.

\logo{PathTo/filename.png}

  • A logo may only be used within a \styleN command that has option [logo].

  • If necessary, the line containing the logo will be padded above and below, to occupy three lines. That avoids smashing it into adjacent lines.

  • Its width and height may not exceed 0.32in (144px @ 600px/in).

    That is: 96px @300px/in, or 192px @ 600px/in, etc.

  • The enclosing \styleN may scale its text, but it will not scale the logo.

  • The logo will be horizontally padded to occupy 3em, at normal (unscaled) font size.

  • The lower 1/4 of the logo sits below the surrounding text baseline.

  • The unstarred \logo and the starred \logo* behave the same as the other unstarred and starred graphics commands.

  • Example: \style5[logo]{Pathetic Press \logo{images/pp-logo.png} Brisbane Paris}

    Pathetic Press Brisbane Paris

 

Command: \sceneimage (Also \sceneimage*)

TOP

Usually, scene breaks do not use images. You may use an ordinary \image as scene break, but the \sceneimage command is specially designed for this purpose.

Typically, the image will be rasterized text in a prominent font. Intead of black, it will be some shade of gray, so that it is not too prominent. The font does not need to be one of the Novelette fonts, as long as its license permits commercial usage in rasterized form.

Usage: \sceneimage[option]{PathTo/filename.png}.

  • The image does not float.

  • The starred \sceneimage* and unstarred \sceneimage behave the same as the corresponding \image* and image commands.

  • Horizontal alignment is the \setscene setting, or default center.

    The only option [align=A], where A is one of left right center, allows local over-ride.

  • Maximum image width is 3.4in. Maximum image height is 0.32in. These apply regardless of trim size or layout.

  • The image is automatically padded to occupy a total of 3 lines. If you wish, use \blankline above and/or below.

  • The following paragraph is not indented.

  • Example, with sceneimage "FOURTEEN" in a decorative font:

    and then they went away\par
    \sceneimage{images/sc14.png}
    The next day, they returned.

    Result:

    and then they went away.

    The next day, they returned.

 

Shell Scripts

TOP

In its documentation utilities folder, Novelette provides several shell scripts. These are coded for Linux or Linux-compatible shells (including Mac OS/X and Android/Termux). If you are on Windows, use the Linux subsystem.

These scripts will take off‑spec image files, and convert them to on‑spec. You will probably need to do this for preview and final modes. Instructions are in utilities.

The scripts require ImageMagick, which can be installed via your Linux distribution.

What they do: Most printers do not care about image specs; anything that can be printed on your home or office printer, is acceptable to them. But the strictest standards, still used by many print-on-demand services, require that the images do not contain any color profile or internal metadata that is not minimally necessary. Above all, grayscale images must be single-channel gray without transparency, rather then the RGB grays that most graphics programs create. The scripts fix these problems.

Since you cannot control whether your print jobs will be sent to slack or strict printers, Novelette requires strict.

Also, the paper and process used for your book cannot produce photo-quality grayscale images. Print services advise that grays near black should become black, and grays near white should become white. The scripts do this, so that your processed images, when viewed on monitor, will more closely resemble how they will print.
