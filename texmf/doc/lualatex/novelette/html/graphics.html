Overview

Novelette does not use the standard LaTeX \includegraphics command. You cannot include any of these formats: pdf eps svg jpg. You cannot draw TiKz diagrams, or use pstricks drawings. Instead, you are limited to monochrome or grayscale raster png images.

You must declare how much space each image will occupy, in terms of the integer number of text lines that it displaces. In draft mode, Novelette does not look for an image file, but prints a placeholder at its declared size. Since the file does not need to exist, you may “write now, do graphics later”.

Once you have an image, you may request that it print instead of its placeholder. As long as the image fits its declared size, its position will match the placeholder; text line breaks and page breaks will remain unchanged. If the image is smaller than declared (the usual situation), it is padded to fit its declared size. But if it is too large, error; the placeholder remains.

Draft mode does not check image files for print-ready specifications. But when you switch to preview or final mode, each image is tested. Any failure demotes to draft mode. You can repair the image using scripts in Novelette's documentation utilities folder. By enforcing specifications, Novelette improves the likelihood that copies of your book, printed by various manufacturers, will be more consistent.

Novelette is intended for text fiction, not picture books or graphic novels. Excessive image clutter will not look good; for that you need a page layout program.

Print-Ready Specifications

  • All image files must be png format, either monochome (1-bit per pixel), or single-channel grayscale without transparency (8-bits per pixel).

  • The image files must state their resolution (density) in pixels/inch or pixels/cm. Most graphics programs do this automatically.

  • In draft mode, most specifications are not checked (saves time). Do not be surprised if an image can be printed in draft mode, but is rejected in preview and final modes.

  • In preview and final modes, images must meet additional print-ready specifications: no color profile, no transforms, no private metadata.

    Unless you have expertise with a professional graphics program (and even if you do!) it is unlikely that your images will meet these specifications. Novelette provides scripts in its documentation utilities folder, which will apply the specifications. Requires ImageMagick. Instructions accompany the scripts.

Best Practices

  • In the same folder as your main document, create a subfolder containing the native-format graphics files for all your images. Then, if you need to change anything, you know where the originals are kept. This is especially important if someone else creates graphics for you: Be sure to request native format, as well as exported png format files.

  • In the same folder as your main document, create a subfolder containing all the finished png images that will be used in the book interior. This folder may contain its own subfolders, with images sorted as you wish. Maximum 5 levels down from the main document.

  • In the same folder as your main document, create a subfolder containing whatever is needed for the book cover. Although Novelette does not do cover artwork, you need to be sure that the cover files travel with the rest of the book.

  • For monochrome, design images at 600px/in or greater. Maximum 1200px/in. For grayscale, the most common value is 300px/in. Usually, there is no advantage to higher grayscale resolution. If your print service requests specific values, use them.

  • Grays near-black and near-white do not print as expected. Do not expect photo-quality grays, because the printing process (and paper) used for your book will not be the same as ordinary home and office printers. Design your images with this in mind.

  • Line art (drawings) will look best when lines (and gaps between them) are about 0.75pt wide, or more. That is 3 pixels for grayscale at 300px/in, or 6 pixels for monochrome at 600px/in.

  • In a grayscale image, these will be hard to read: gray text, text against a gray background, light text against a dark background. If necessary, use larger font size, heavy (bold) fonts, or fonts (such as sans-serif) without fine details.

  • Novelette does not provide captions or borders. If you need those things, you must design them into the images. There are no transforms; images cannot be flipped, rotated, cropped, or scaled within Novelette.

Paths to Image Files

These are essentially the same rules used for sub-documents:

  • An image file must be located in the same folder as the main document, or in a subfolder from there.

  • When using sub-documents, all paths to images are relative to the main document, not relative to the sub-document files. Thus, any sub-document may call any image, with proper path from main document.

  • The paths and filenames may contain letters (case-sensitive), numerals, hyphen, underscore, and period. They may not contain spaces, asciitilde, backslash, or other characters that are not platform-independent paths or file names.

  • Do not use any LaTeX code in the path or filename. For example, if the actual filename is dèjá.png then do not request d\`ej\'a.png.

    • Since all paths must be relative to the main document, any path beginning with / or C:// (or something similar) will be rejected. And since any path must not lead outside the main document folder, any path containing ../ will be rejected. Any path that resolves to a symlink (softlink) will be rejected.

  • For developer testing purposes, Novelette contains a few generic images in the same folder as novelette.cls. These can be used by filename alone, without path. But an ordinary user is unlikely to need them.

Image Dimensions

This applies to ordinary images, using the \image command. The \sceneimage command has different requirements.

  • Run a test document with your Preamble settings, in draft mode. The Terminal Summary will show the textwidth, font em size, and baselineskip. These are specific to your settings. If you change anything in Preamble, then the values will change.

  • The maximum width of an image depends only on the textwidth. For example, if the textwidth is 4.2in, a grayscale image at 300px/in cannot exceed 4.2*300 = 1260px width.

  • The maximum height of an image depends on font em size, baselineskip, and number of text lines that the image will displace. The number of lines is declared as option for the \image command.

  • EQUATION for calculating the maximum height of an image: P is its maximum height in pixels, L is the declared number of lines, em and baselineskip are measured in pt, and R is the image resolution in pixels/inch:

    P = R*[0.84*em + (L-1)*baselineskip] / 72.27

    For example, if R=300px/in, L=5, em=11.7pt, and baselineskip=14.8pt:

    Max height = 300*[0.84*11.7+(5-1)*14.8]/72.27 = 286 pixels.

    The actual calculation is a little more than 286, but the value must be truncated down to an integer value. Never rounded up.

  • Or, if you already know the pixel height, you may calculate the minimum number of lines required:

    L = 1 + [(72.27*P/R) - .84*em] / baselineskip

    Round L up (never down) to nearest integer.

  • Unsure of the book trim size, or other Preamble settings? If you design images so that they do not exceed 3.4in width and 3.4in height, then they will fit all sizes provided by Novelette, although the number of displaced lines will vary.

    That height allows for at least 7 lines of text on the same page as an image. Better results will be obtained if you first decide on trim size and layout, then decide on the displacement for each image, then design the images.

  • When an image is at or near its maximum height, the above and below clearance to text will be adequate, but not very great.

The \image Command (Also \image*)

Usage: \image[option]{PathFromMainDocumentTo/filename.png}
Option: [lines=L,align=A,float=F,tweak=T]

  • L is an integer >= 1.

    If the image is located in a component with [single] option, then max L is lines per page. Elsewhere, max L is 20.

    Although it is written as an option, each image must declare its number of lines. There is no default value.

    Whether or not the image floats, it will displace that number of lines of main text (or the equivalent).

  • A is one of left right center.

    Horizontal alignment. Default center.

  • F is one of none here top bottom.

    In frontmatter, backmatter, and component display areas, only none permitted; it is the default.

    In main text, the default is here. Novelette automatically uses top as fallback for here.

    There are no page floats. If you need an image on a page by itself, use a component environment with [single] option. Then the image can (if desired) occupy the full textblock. This should never be done in the middle of a chapter, where it would break the text flow.

  • T is one of up down mid.

    When the height of an image is less than its maximum (for any particular lines=L), it will be padded above and/or below. Tweak changes where padding is applied. Choice up moves the image as high as it can go (all padding beneath). Choice down moves the image as low as it can go (all padding above). Choice mid is the default, which splits the padding.

    Tweak does not change where an image floats, and does not change the number of displaced lines.

Mandatory: {PathFromMainDocumentTo/filename.png}

  • In draft mode, unstarred \image does not look for an image file. It prints a placeholder, whether or not the file exists. You may use empty braces, or write a short note, such as {Map of Whereville}, as a reminder to yourself.

    If you write a reminder, do not use macros such as \textit or \smcp. Do not use diacritical codes such as \'E for Eacute. The reminder will print as a label, within the placeholder area (no more than final 32 characters).

  • In draft mode, starred \image* looks for its image file. If the file exists in an allowed folder, has png file extension, and fits in its reserved area, then it prints. Otherwise, error, and a placeholder prints. In any case, the image is not inspected for specifications; an off-spec image (such as color, or gray with transparency) prints without error or warning.

  • In preview and final modes, \image and \image* are the same. The file must exist in an allowed folder, fit its reserved area, and meet all print-ready specifications. Otherwise, error, and a placeholder prints.

  • Image placeholders occupy the correct number of lines, and have the correct float, alignment, and tweak. But since the height and width of the real image is unknown, the placeholder size is guessed at slightly smaller than the maximum possible size.

The \sceneimage Command (Also \sceneimage*)

Usage: \sceneimage[option]{PathFromMainDocumentTo/filename.png}
Option: [align=A]

This command has a special purpose: It is one of several ways to separate scenes within a chapter. For details, see how components are structured.

The command performs like \image and \image*, but with these exceptions:

  • The only option is [align=A], where A is one of left right center. Default center (but this is not necessarily best).

  • Maximum image width is 3.4in, which is more than any good-looking scene break needs. Maximum image height is 0.24in. These apply regardless of trim size or layout.

  • The image never floats. It is automatically padded above and below, to occupy a total of 3 lines.

Shell Scripts

In its documentation utilities folder, Novelette provides several shell scripts. These are coded for Linux or Linux-compatible shells (including Mac OS/X and Android/Termux). If you are on Windows, use the Linux subsystem.

These scripts will take off-spec image files, and convert them to on-spec. You will probably need to do this for preview and final modes. Instructions are in utilities.

The scripts require ImageMagick, which can be installed via your Linux distribution.
